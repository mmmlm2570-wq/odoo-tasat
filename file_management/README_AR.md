# إدارة الملفات — Odoo 19

هذه الحزمة تضم مسارين لنفس الفكرة:

1. **Odoo.sh أو Odoo محلي/مستضاف ذاتياً:** ثبّت الإضافة `file_management` الموجودة هنا.
2. **Odoo Online:** لا يمكن تحميل أو تثبيت كود Python/XML مخصص على Online. اتبع قسم **تنفيذ Odoo Studio** أدناه. لا يحتاج هذا المسار أي مكتبات أو وصول للخادم.

> ملاحظة: الاعتماد الوحيد للإضافة هو `base` القياسي. لا توجد مكتبات خارجية.

## الوظائف

- تطبيق باسم **إدارة الملفات**.
- شاشة قائمة مع بحث وفلاتر حسب القسم والتاريخ والمُضيف، وعرض Kanban بسيط.
- نموذج لإضافة الاسم والوصف والقسم والملف وتاريخه والملاحظات.
- تحميل الملف من الحقل نفسه، وتحميله لاحقاً بالنقر على اسم الملف في بطاقة المرفق.
- استبدال المرفق بإعادة اختيار ملف في الحقل نفسه.
- أسماء وتواريخ الرفع محفوظة تلقائياً في `create_uid` و`create_date`.
- مستخدم الملفات: قراءة كل الملفات، إضافة ملف، وتعديل ملفاته فقط، دون حذف.
- مدير الملفات: تحكم كامل بكل الملفات والتصنيفات، بما في ذلك الحذف.

## التثبيت على Odoo.sh أو خادم يدعم الإضافات المخصصة

1. انسخ مجلد `file_management` كما هو إلى مجلد إضافات مخصص في مستودع Odoo.sh، مثل `addons/file_management`.
2. أضف مجلد الإضافات إلى `addons_path` إن لم يكن موجوداً. في Odoo.sh يكفي عادة حفظه داخل مستودع الـ Git في مجلد الإضافات المخصص.
3. ارفع التغييرات إلى GitHub ثم شغّل/ادمج بناء Odoo.sh.
4. افتح قاعدة الاختبار، فعّل وضع المطوّر، ثم **Apps → Update Apps List**.
5. ابحث عن **إدارة الملفات** واضغط **Install**.
6. من **Settings → Users & Companies → Users**، امنح الأشخاص أحد الدورين:
   - **إدارة الملفات / مستخدم**: إضافة وقراءة وتعديل ملفاته.
   - **إدارة الملفات / مدير**: كامل الصلاحيات.

لا تثبّت الحزمة على قاعدة إنتاج قبل اختبارها في فرع/قاعدة تجريبية.

## تنفيذ Odoo Studio على Odoo Online

يتطلب Studio (والاشتراك Custom). افتح **Studio** من لوحة التطبيقات ثم اتبع التالي:

### 1. إنشاء التطبيق والنموذج

1. اختر **New App**.
2. اكتب الاسم: `إدارة الملفات`، واسم النموذج المقترح: `ملف`.
3. أضف حقل **Text** باسم `اسم الملف` واجعله Required.
4. أضف حقل **Multiline Text** باسم `وصف مختصر`.
5. أضف حقل **Many2one** باسم `التصنيف`، ثم اختر **New Model** وسمّه `تصنيف الملفات`. أضف إلى نموذج التصنيفات حقل Text Required باسم `الاسم`.
6. أضف حقل **File** باسم `المرفق`. أضف أسفله حقل Text باسم `اسم المرفق`، ثم من خصائص حقل المرفق اختر هذا الحقل في **Filename** إذا ظهر الخيار.
7. أضف حقل **Date** باسم `تاريخ الملف` واجعل القيمة الافتراضية Today.
8. أضف حقل **Multiline Text** باسم `ملاحظات`.
9. لا تنشئ حقلي «تاريخ الرفع» و«رفعه بواسطة»: استخدم الحقلين القياسيين **Created on** و **Created by** من قائمة **Existing Fields**. هذان يسجلان المعلومات تلقائياً.

### 2. شاشة القائمة والبحث

1. افتح عرض **List** داخل Studio.
2. أضف الأعمدة بالترتيب: اسم الملف، التصنيف، تاريخ الملف، Created on، Created by.
3. اجعل `اسم الملف` هو العنوان، وفعّل البحث عليه وعلى الوصف من خصائص الحقول إن أتاح الإصدار ذلك.
4. في شريط البحث أضف فلاتر محفوظة: `تصنيف الملفات`، `تاريخ الملف`، `Created by`، و`Created on`؛ وأضف Group By للتصنيف.
5. اختياري: أنشئ **Kanban** وضع العنوان ووسم التصنيف وتاريخ الملف. لا تُضف وظائف إضافية؛ القائمة هي العرض الافتراضي الأنسب.

### 3. التصنيفات الافتراضية

افتح تطبيق **إدارة الملفات → التصنيفات** وأنشئ السجلات الآتية مرة واحدة:

`عقود`، `فواتير`، `مستندات`، `مراسلات`، `ملفات الموظفين`، `ملفات العملاء`، `أخرى`.

### 4. الصلاحيات

من Studio افتح **Access Rights** وأنشئ مجموعتين:

| المجموعة | الملفات | التصنيفات |
|---|---|---|
| إدارة الملفات / مستخدم | Read + Create؛ Write لملفاته فقط؛ Delete غير مسموح | Read |
| إدارة الملفات / مدير | Read + Create + Write + Delete | كل الصلاحيات |

لجعل «مستخدم» يعدل ملفاته فقط، أنشئ في **Settings → Technical → Security → Record Rules** (بعد تفعيل وضع المطوّر) قاعدة على نموذج الملفات للمجموعة مستخدم، بالنطاق: `[("create_uid", "=", user.id)]` للتعديل فقط. اترك القراءة عامة للمجموعة كي تظهر لها الملفات المسموح عرضها حسب التصميم البسيط. إذا لم تظهر شاشة قواعد السجلات في اشتراكك، اجعل صلاحية Write للمستخدم غير مفعّلة؛ ستبقى الإضافة والقراءة متاحتين بأمان.

### 5. الاستخدام اليومي

يفتح المستخدم التطبيق ويضغط **New / إضافة ملف**، يملأ الحقول ثم ينقر منطقة المرفق لاختيار ملف من جهازه ويحفظ. لعرض المعلومات يفتح السطر. لتحميل المرفق ينقر اسمه، ولاستبداله يختار ملفاً جديداً في نفس الحقل. الحذف متاح للمدير فقط.

## حدود Odoo Online

يمكن رفع ملفات عبر حقل Studio File مباشرة، لكن الحد الأقصى للملف المرفوع إلى Odoo Online هو 64MB. وللتحكم المتقدم جداً على مستوى ملف/مجلد، قد يكون تطبيق Documents القياسي خياراً أفضل من تطبيق Studio جديد.

## ملاحظات فنية

- الحقل `file_data` ثنائي (`Binary`) ويُخزّن كمرفق في Odoo (`attachment=True`).
- `create_uid` و`create_date` حقول Odoo قياسية، ولا يمكن تزويرهما يدوياً.
- لا توجد أتمتة، واجهات JavaScript، أو اعتماديات خارجية.
